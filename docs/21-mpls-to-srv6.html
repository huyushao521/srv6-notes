21 · SR-MPLS 到 SRv6 的共存与迁移

本章定位：补章。前面 20 章默认你手上是一张"纯 SRv6 网"。现实是：没有运营商会一夜把 SR-MPLS 换掉，中间必然有三到五年的双轨期——同一台设备跑两套段路由，同一个 VPN 跨越两种封装，同一批运维同时看两套 OAM。这一章讲这三年怎么活。

一句话概括：迁移的难点不在协议，在"两套平面必须在同一个故障域里共存"——任何一次割接，都要能在一分钟内退回去。

本章要拿到的东西：

问题 对应小节
SR-MPLS 与 SRv6 哪些概念能一一对应，哪些不能 21.2.1
双栈节点怎么同时跑两套 SID 空间 21.2.2
一个跨 MPLS/SRv6 的 L3VPN 怎么拼起来 21.3
先换核心还是先换边缘 21.4
割接失败，五分钟内怎么退回去 21.5
双轨期的监控为什么总会漏 21.6

21.0 本章拓扑

图 21-1：典型双轨期（三个域，两种封装）

   ┌── MPLS 域（存量，SR-MPLS）──┐   ┌── 双栈边界 ──┐   ┌── SRv6 域（新建）──┐
   │                              │   │              │   │                      │
   PE-A ── P1 ── P2 ── BR-1 ══════╪═══╪══ BR-2 ══════╪═══╪══ P5 ── PE-B         │
   (SR-MPLS)                    │   │  (SRv6+MPLS) │   │   (纯 SRv6)           │
   └──────────────────────────────┘   └──────────────┘   └──────────────────────┘
        标签栈转发                        标签 ↔ SID 映射        DA 转发

  SID / 标签约定：
    MPLS 域：SRGB 16000-23999；PE-A 的 Node SID 16001
    SRv6 域：Block fc00:0::/32；PE-B locator fc00:0:2::/48，End.DT4 fc00:0:2:e109::
    边界：BR-2 同时有 label 16002 与 SID fc00:0:12:e000::
角色 需要跑的平面 备注
PE-A 仅 SR-MPLS 存量业务不动
P1 / P2 仅 SR-MPLS 越简单越好
BR-1 SR-MPLS 域内最后一段标签栈
BR-2 双栈 唯一做封装转换的节点，也是唯一的高风险点
P5 / PE-B 仅 SRv6 新建业务

21.1 为什么不能让 SR-MPLS "就地升级"

Segment Routing can be instantiated on the MPLS data plane or on the IPv6 data plane. The two instantiations share the same control plane concepts but use different forwarding instructions.

段路由可以实例化在 MPLS 数据面或 IPv6 数据面上。两种实例化共享同一套控制面概念，但转发指令不同。

这句话是迁移设计的全部依据：控制面可以复用，转发面必须翻译。具体到落地上：

维度 能不能复用 原因
IGP 扩展（prefix-SID、adj-SID 概念） 概念可复用，编码不同 MPLS 用 Label 子 TLV，SRv6 用 Locator + End.X SID 子 TLV
BGP VPN 路由 基本可复用 RD/RT 一致，只换封装属性
SR Policy 不可复用 MPLS 段列表是标签栈，SRv6 是 SID 列表
OAM 不可复用 MPLS LSP ping 与 SRv6 ping 是两套
业务配置（VRF/AC） 可复用 与转发面无关

结论：控制面先做，转发面后做；业务配置不动，封装逐个替换。

21.2 三种共存形态

21.2.1 概念映射表

SR-MPLS SRv6 能否一一对应
Label（20 bit） SID（128 bit） 语义对应，长度不对应
SRGB（标签池） Block + Locator SRGB 是全局池，Block 是地址段
Node SID End SID 对应
Adj-SID End.X SID 对应
LAN-Adj-SID LAN End.X SID 对应
Binding SID BSID 对应（18.4）
标签栈深 容器数（19.3） MPLS 可压几百层，SRv6 受 6 段/容器限制
PHP（倒数第二跳弹栈） PSP（倒数第二跳剥外层） 对应
显式空标签 3 无对应 SRv6 无"隐式空"概念

最容易被忽略的一行是标签栈深。MPLS 可以轻松压 10 层标签做跨域严格路径；SRv6 压 10 段就要 SRH，压缩后仍要 2 个容器。所以从 MPLS 迁过来的 TE 策略，段数必须重算，不能照搬。

21.2.2 双栈节点的两套 SID 空间

边界节点同时维护 SRGB 与 Block，互不干扰：

segment-routing
 mpls
  global-block 16000 23999
 !
!
segment-routing
 srv6
  locator BR2
   micro-segment behavior unode psp-usd
  !
 !
!

两条硬约束：

  1. 不能把 SRGB 的标签值直接当作 Block 的一部分"对齐一下好看"——两者语义不同，混用会导致 BGP-LS 上报的拓扑出现两份同一节点的 SID，控制器算路时随机选，故障极难复现。
  2. 双栈节点必须同时通告两套拓扑（BGP-LS 里表现为同一 Node 带两组属性），否则控制器在跨域算路时看不到它。

21.3 一个跨域 VPN 怎么拼起来

这是迁移期最典型的业务：总部在 MPLS 域，分支在 SRv6 域，要求互通。

21.3.1 拼法一：BGP VPN 路由跨域传递（推荐）

图 21-2：VPNv4 路由跨越两种封装

   PE-A（MPLS）                          PE-B（SRv6）
      │                                      │
      │ 1. VPNv4 路由 + Label 16001          │
      ├────────────> BR-2 ──────────────────>│
      │              2. 重写封装属性：        │
      │                 Label → End.DT4 SID   │
      │                （fc00:0:2:e109::）    │
      │                                      │ 3. 本地 VRF 安装
      │                                      │    下一跳 = SID

关键点：

  • RD/RT 完全不动，业务策略（import/export）零改动；
  • 只改下一跳的封装属性：从"压标签"变成"压 SID"；
  • 反向同理，BR-2 把 SRv6 侧来的 SID 换成标签再送进 MPLS 域。

配置上就是边界节点做一次 route-policy 重写（IOS XR 示意）：

route-policy MPLS2SRV6
  if extcommunity rt matches-any (65000:100) then
    set path-selection backup 1 install
  endif
end-policy
!
! 实际封装转换由平台内部完成：VPNv4 的 Label 字段
! 在 SRv6 侧被解释为 End.DT4 SID，需要在边界显式映射

21.3.2 拼法二：SID 映射表（草案方向）

The SRv6 SID and the MPLS label can be mapped to each other at the domain boundary, so that a packet can traverse both domains without changing the service encapsulation.

在域边界把 SRv6 SID 与 MPLS 标签互相映射，使报文跨越两个域时不必改变业务封装。

优点 代价
业务侧完全无感 边界要维护映射表（规模 = 跨域前缀数 × 域数）
适合大规模跨域 草案阶段，互通性需实测
保持端到端语义 映射表不同步会造成静默黑洞

这条路线目前以草案推进（SRv6-MPLS interworking），落地前必须做两家设备对接实测，不要按"标准已定"来设计。

21.3.3 拼法三：6PE/6VPE 过渡（最保守）

如果只是"让 SRv6 域的业务能到 MPLS 域"，最保守的做法是不动 VPN，用 6PE/6VPE 把 IPv6 前缀带过去。代价是放弃端到端 SRv6 语义（到了 MPLS 域就退化成普通转发），收益是改造量接近于零。

选型建议：

场景 选哪种
少量跨域业务，SLA 要求不高 拼法三（6PE/6VPE）
跨域业务多，要保留 TE 拼法一（BGP 重写封装）+ 边界 SR Policy
大规模、多运营商互通 拼法二（映射表），先做小范围试点

21.4 替换顺序：先核心还是先边缘

两种主流打法，各有代价，不要混着用。

21.4.1 打法一：核心先行

图 21-3：核心先行（由内向外）

  Step 1  核心 P 节点换 SRv6（同时保留 MPLS 转发）
  Step 2  核心跑通 SRv6 转发（业务仍走 MPLS）
  Step 3  逐台 PE 升级为双栈
  Step 4  新业务直接上 SRv6
  Step 5  存量业务按 VRF 逐个切换封装
优点 风险
核心容量早释放（表项规模下降） 双栈期最长，核心节点承担全部风险
边缘改造可以慢慢来 核心故障影响全网

21.4.2 打法二：边缘先行

图 21-4：边缘先行（由外向内）

  Step 1  新建 / 扩容的 PE 直接上 SRv6（双栈）
  Step 2  新增业务走 SRv6，老业务留在 MPLS
  Step 3  边缘双栈比例达阈值（经验值 60%+）
  Step 4  核心一次性切换
优点 风险
存量业务零打扰 双栈边缘多，运维复杂度前置
可随时暂停 核心切换仍是一次性动作，窗口要留足

选择依据不是技术，是业务分布：新业务占比高（云、政企、5G）选边缘先行；存量 IRR 业务为主（专线、语音）选核心先行。

21.5 回退设计：割接窗口里最重要的一页

任何一次 SRv6 割接，回退方案要和割接方案同日评审、同日演练。四个层次：

层次 回退动作 耗时 影响
业务级 VRF 的封装策略改回 MPLS 分钟级 单 VRF 中断数秒
节点级 双栈节点的 SRv6 locator 撤销通告 秒级 该节点流量回 MPLS
域级 边界停止 SID ↔ Label 映射 秒级 跨域业务回退
全网级 IGP 里去掉 SRv6 能力标识 分钟级 全网回 MPLS

工程实践三条：

  1. locator 的撤销必须比"配置删除"更快：先撤通告（秒级生效），再删配置。顺序反了会造成一段黑洞。
  2. 保留 MPLS 转发面至少 6 个月，即使业务已全部迁移。这是唯一能在事故中"一键回退"的保险。
  3. 回退演练要在低峰期做过一次，只写在文档里的回退方案等于没有。

21.6 双轨期运维的五个坑

坑 现象 对策
OAM 双套 ping 通但业务不通，因为 ping 走的是另一套平面 明确"SID ping 验 SID 平面，标签 ping 验标签平面"，巡检脚本分开
ACL 双写 新规则只写在一侧 规则模板化，按"域"生成两套
监控指标不同名 同一链路两个系统两套计数器 统一到 YANG 模型（第 24 章）
容量账重复算 双栈节点上 SRv6 与 MPLS 各占一份表项 按"双栈=1.8 倍表项"规划
BGP-LS 拓扑重影 同一节点上报两份 SID 控制器侧按 Router-ID 去重，保留两套属性

最后一条最容易出事：控制器把双栈节点当成两个节点算路，结果算出一条"在 MPLS 域和 SRv6 域之间反复横跳"的路径。

21.7 本章小结

记住这一条 为什么
控制面可复用，转发面必须翻译 业务配置不动是迁移能成的前提
标签栈深 ≠ 段列表长度 老 TE 策略不能照搬，段数要重算
双栈节点必须通告两套 SID，但控制器要会去重 否则算路会出现"幽灵节点"
边界是唯一转换点 转换点越少，故障面越小
回退方案与割接方案同时评审 只写在文档里的回退等于没有
MPLS 转发面至少保留 6 个月 唯一的保险

实战案例

案例 A：割接后总部到分支时通时不通

现象：总部（MPLS 域）访问分支（SRv6 域），业务 30% 丢包，且丢包与时段无关。

排障分支：

检查项 位置 期望值 实际值
边界节点是否双栈通告 show bgp link-state 同节点两组属性 两组都有
控制器的拓扑节点数 控制器 与真实节点数一致 多出 1 个
算出的路径 PCEP 日志 单域内 跨域往返一次
边界 CPU SNMP < 40% 65%（映射表查两次）

根因：控制器未做 Router-ID 去重，把 BR-2 当成两个节点，算出"BR-2(MPLS) → BR-2(SRv6) → 回 BR-2(MPLS)"的路径，报文在边界节点被反复映射，部分包因 TTL 耗尽被丢。

修复：控制器加去重逻辑；边界节点同时配置 router-id 显式一致。教训：双栈期控制器版本要与设备能力同步升级。

案例 B：迁移后语音业务单通

现象：专线业务迁移到 SRv6 后，语音能拨通、单向无声。

期望值判定表：

检查项 MPLS 时代 SRv6 后
双向路径一致性 同一标签栈来回 去程 SRv6、回程 MPLS（不对称）
MTU 1500 去程多 128 B SRH，超过某段 1500
分片 无 去程大包被丢（不分片）

根因：去程走 SRv6（带 SRH），回程走 MPLS（无 SRH），单向 MTU 不足导致大包丢弃，语音的信令包（小）通过、媒体包（大）丢失。

修复：边界统一 MTU 预算（按 SRv6 侧算），或对语音开启压缩（第 19 章）。教训：单通问题先看"来回路径是否对称"，再看 MTU。

案例 C：回退演练时回不去

现象：割接演练中按文档执行回退，MPLS 业务恢复用了 12 分钟，超出 5 分钟目标。

判据：

步 文档预期 实际
撤销 SRv6 locator 通告 5 秒 5 秒
业务 VRF 恢复 MPLS 封装 30 秒 11 分钟
结论 — 阻塞点在封装策略依赖 BGP 重新收敛

根因：封装切换依赖 BGP VPN 路由的重刷新，未做"双下一跳预安装"（PIC）。修复：迁移前先开 BGP PIC，让两套封装同时预装在 FIB 里，回退时只切指针。
